# 기존 스킬과 비교

1. 방·절대 기간·출력 목적을 고정한다. 동일한 원문 집합을 한 번 수집해 두 방식에 제공한다. 날짜 경계, 댓글, 이미지, 삭제 메시지와 누락 범위를 기록한다.
2. 로컬 출력 열람 전에 Codex 직접 분류 기준을 저장한다. 이는 비교 기준이지 독립적인 정답이 아니다. 정확도라고 부르려면 사람이 검토한 정답이 별도로 필요하다. 원문 해시와 질문 해시를 기록한다.
3. 설치/다운로드, UI 수집, 최초 모델 로딩, 반복 분류, Codex 재검토/출력 시간을 분리한다. 분류기만 빠르다고 전체 워크플로 개선으로 발표하지 않는다.
4. 도우미는 첫 요청·요청별 중앙값·p95·전체 HTTP 처리 시간을 기록한다. 로딩 시간은 서버 응답 필드로 별도 확인한다. 콜드 테스트는 이 실험이 시작한 모델을 명시적으로 언로드한 뒤 한다. 반복 테스트는 같은 입력으로 새 결과 파일을 만든다.
5. 업무/목적 관련 여부와 의도 일치율, 중요 요청 누락, 완료·취소를 새 업무로 만든 오류를 각각 확인한다. 혼합 의도·맥락 의존·애매한 발언은 따로 보고한다. 거절·잘림·API 오류도 분모와 실패 건수에 포함한다.
6. CPU·RSS는 서버 및 별도 추론 프로세스까지 포함해 기준 상태·실행 중·종료 후를 측정한다. 샘플링 RSS 최고치는 OS가 보고하는 진짜 peak와 구분한다. 시간·메모리 계측이 불가능하면 미측정으로 남긴다.

과거 실행이 UI 복구·사용자 대기를 포함하거나 범위가 다르면 이번 분류 시간으로 나눠 '몇 배 빠름'을 계산하지 않는다. Codex의 순수 추론 시간을 얻지 못했으면 그 항목은 미측정이다. Codex 기준과 Laya의 일치율은 Laya의 정확도나 Codex의 정확도가 아니다.

공개 가능한 것은 가상 입력과 검증 절차, 사용자 허용 범위의 비식별 집계뿐이다. 실제 채팅 원문, 닉네임, 방 이름, 초대 URL, 캡처, 민감한 사건 정보는 공개하지 않는다. 가상 예시는 실제 대화를 단순 치환하지 말고 새로 작성한다.
