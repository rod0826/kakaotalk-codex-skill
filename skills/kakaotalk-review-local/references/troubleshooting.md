# 수집 문제 대응

다음은 macOS 실사용에서 관찰한 복구 방법이다. 다른 버전에서도 항상 재현되는 조건으로 단정하지 않는다.

## 스크롤·클릭이 실패할 때

- 새 상태에서 대상 창 제목과 요소 번호를 다시 확인한다. 사용자 조작으로 창이 바뀌면 기존 좌표·요소 번호를 버린다.
- 일반 스크롤이 실패해도 스크롤 영역에 노출된 `Scroll Up` / `Scroll Down` 보조 동작은 작동할 수 있다. 실제로 노출된 동작만 사용한다.
- 실제 수집 중에는 묶음마다 상태를 읽고 누락을 확인한다. 이미 읽은 구간으로 이동하는 경우에만 연속 스크롤을 묶어 실행한다.
- 스크롤 막대 값을 직접 설정하면 과거 메시지 로딩으로 값이 바뀌거나 긴 지연이 발생할 수 있다. 목표 위치에 도착했는지 다시 확인한다.

## 사진 뷰어를 닫았는데 응답이 없을 때

- Computer Use 표시가 창 닫기 아이콘을 가리는지 확인한다. 보이는 메뉴의 `창 → 창 닫기` 같은 대안을 사용할 수 있으나 성공 여부를 확인한다. 모든 창 닫기·앱 강제 종료를 대신 실행하지 않는다.
- 시간 초과만으로 앱 전체가 멈췄다고 판단하지 않는다. 도구가 이미 닫힌 뷰어를 참조할 수 있으므로 앱을 다시 연결하고 현재 창 제목을 확인한다.
- 재연결 후에도 복구되지 않을 때만 사용자가 뷰어를 직접 닫고 지정 채팅방으로 돌아오도록 요청한다. 이미 닫았다는 답을 받으면 같은 조작을 반복 요청하지 않는다.
- 같은 문제가 반복되면 뷰어를 계속 열지 말고 화면의 이미지와 본문으로 진행하며, 판독하지 못한 이미지를 결과에 표시한다.

## 댓글이 누락되거나 잘못된 창이 열릴 때

- 전체 댓글 목록이 현재 날짜의 글을 표시하지 않으면 그 목록만으로 해당 날짜 댓글이 없다고 판단하지 않는다.
- 대상 메시지의 댓글 수 버튼이나 제공된 댓글 동작을 사용한다. 댓글 메뉴가 작성 모드만 켜거나 기존의 다른 댓글 창을 활성화할 수 있다. 부모 메시지·발신자·날짜를 확인한 다음 읽는다.
- 댓글 입력창과 본문 검색창을 구분한다. 읽기 작업에서는 댓글을 입력·전송하지 않는다. 열었던 작성 모드는 닫고, 다른 댓글의 답을 현재 질문의 답으로 연결하지 않는다.
- 최초 목록에 일부만 로딩될 수 있다. 끝으로 이동해 추가 로딩과 마지막 메시지를 확인한다. 본문에도 공유된 댓글은 중복 집계하지 않는다.

## 부분 결과를 낼 때

현재 지점과 문제를 확인하고 대체 경로 또는 재연결을 한 차례 시도한다. 동일 지점에서 두 차례 진행이 없으면 같은 동작을 반복하지 말고, 확인한 구간·미확인 구간·해결에 필요한 사용자 조작을 구체적으로 알린다. 회복되면 이어서 수집하고, 회복되지 않으면 부분 결과를 전달한다. 전체 수집을 마쳤다고 표현하지 않는다.
