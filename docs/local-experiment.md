# 로컬 판단 실험 버전

기존 `kakaotalk-review`는 그대로 유지한다. 새 스킬은 [kakaotalk-review-local](../skills/kakaotalk-review-local/SKILL.md)이며, **Ollaya 0.13.0 + Laya multilingual**을 보조 분류기로 사용한다. 모델 선정의 최종 결론이나 한국어 최적화 완료 버전이 아니다.

## 설치와 사용

```text
$skill-installer로 https://github.com/rod0826/kakaotalk-codex-skill 저장소의
skills/kakaotalk-review-local 스킬을 설치해줘.
```

```text
$kakaotalk-review-local
일반 채팅방 ‘가상 출판 준비모임’의 2026-09-07~09-08 대화를 조회해줘.
전체 요약과 중요 이슈를 정리하고 로컬 분류도 사용해줘.
```

이 예시는 새로 만든 가상 사례다. 방·기간·원하는 결과를 확인하는 워크플로와 접근성 준비는 기존 버전과 같다. 로컬 실행은 [실행 안내](../skills/kakaotalk-review-local/references/local-runtime.md)를 따른다. 화면·텍스트를 Codex가 읽으므로 완전 로컬 처리 도구는 아니다.

## 2026-10-17 탐색 실험 결과

기기: Apple M1 Pro, 메모리 16GB. CPU ONNX FP32, 스레드 4개. 모델 `laya:multilingual`, manifest digest `2840506e1f978aeb696a6f84af43ecc7fca95754cb63a67bafe6132532d384eb`.

사용자가 지정한 하루의 메인 대화에서 수집한 **텍스트 75건**을 같은 순서로 사용했다. 이미지·별도 댓글·삭제 메시지는 이 수치의 입력에서 제외했다. 일부 발언은 화면에 표시된 길이까지만 포함한다. 하루 전체 멀티모달 리뷰의 비교가 아니다. 실제 방·참여자·날짜 범위·대화·캡처·질문별 결과는 공개하지 않는다.

| 항목 | 결과 |
|---|---|
| 최초 실행 75건 | 46.60초 |
| 첫 요청 / 모델 로딩 | 4.91초 / 서버 보고 4.405초 |
| 모델이 로드된 상태에서 같은 입력 재실행 | 42.32초 |
| 재실행 요청별 중앙값 / p95 | 0.542초 / 0.755초 |
| 재실행 중 Ollaya+추론 자식 프로세스 합산 RSS 최고 샘플 | 약 679MiB |
| API 오류·응답 잘림 | 0/75 |
| 두 실행 사이 판정 변경 | 0/75 |
| Codex 기준과 관련성 3분류 일치 | 4/75, 약 5.3% |
| Codex 기준과 주 의도 7분류 일치 | 21/75, 28.0% |
| Codex 순수 추론 시간 / 전체 리뷰 속도 향상률 | 미측정 / 산출하지 않음 |

시간은 각 HTTP 요청을 순차 실행한 Python 프로세스 안에서 `perf_counter`로 측정했다. 재실행 RSS는 0.5초 간격으로 샘플링해 서버와 ONNX 자식의 RSS를 합산한 값이다. 공유 페이지가 이중 집계될 수 있으며 OS peak·전체 시스템 메모리·설치 디스크 크기와 다르다. 재실행 전/후 RSS 합산 샘플은 약 672/666MiB였다. 순간 CPU peak는 측정하지 않았다.

Codex 기준 분류는 로컬 출력을 보기 전에 만들었지만, 독립적인 사람 정답이 아니므로 **일치율은 정확도가 아니다**. 혼합 의도와 짧은 답변에는 해석 여지가 있다. 평가 입력·문맥·질문 설계 한 번에 대한 탐색 결과이며 Laya 전체 성능을 일반화하지 않는다.

관찰: 로컬 모델은 관련성의 대부분을 `unclear`로 분류했고, 요청을 완료·취소로 혼동했다. 이후 별도로 새로 작성한 가상 문장으로 영어/한국어 질문·선택지를 시험했지만, 요청과 완료·일정 변경과 취소를 혼동하는 사례가 남았다. 실제 대화에 맞춰 재학습하거나 질문을 최적화한 결과는 아니다.

**결론: 이 구성은 현재 기본 버전을 대체하지 않는다.** 기존 스킬의 과거 경과 시간에는 다른 범위·이미지·댓글·UI 복구 대기가 있어 이번 시간과 직접 비교할 수 없다. 전량 Codex 재검토가 필요한 현재 구성에서 속도·토큰 절감은 입증되지 않았다.

## 동작 원칙

- 모든 메시지를 보존하고 Codex가 재검토한다. 일상으로 판정됐거나 확률이 높아도 자동 제외하지 않는다.
- 로컬 모델은 관련성과 의도만 보조 판단한다. 담당자 배정·기한·완료·취소 연결·이미지 판단은 Codex가 확인한다.
- 로컬 서버 오류·잘림·잘못된 응답은 미확인으로 남긴다. 도우미는 원문을 결과에 보존하고 부분 실패 시 종료 코드 2를 반환한다.
- 도우미는 loopback만 허용하고 프록시·리디렉션을 사용하지 않는다. 인증이 필요한 기존 서버는 현재 도우미 지원 범위 밖이다.
- 공개 예시에는 새 가상 대화만 사용한다. 실험 원문과 결과 파일은 공개 저장소 밖에 둔다.

코드 검증: `python3 -m unittest discover -s tests -v`. 스킬 형식 검증과 실제 모델 실행을 별도로 수행했다. Windows 런타임·일반 채팅방과 로컬 모델의 전체 결합 동작은 이번 실험에서 검증하지 않았다.
