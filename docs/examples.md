# 가상 사용 예시

이 문서의 방·닉네임·대화·날짜는 설명을 위해 새로 만든 가상 사례다. 실제 테스트 메시지의 내용을 보존한 익명화 자료가 아니다.

## 일반 채팅방: 전체 요약

입력: 일반 채팅방 ‘새봄 프로젝트’, 2026-09-07~08, 전체 요약.

가상 대화:

```text
09-07 14:10 담당자A: 시안 검토 회의는 내일 오후 2시로 정할게요.
09-07 14:12 담당자B: 확인했습니다. 회의 전까지 수정안을 올릴게요.
09-08 11:00 담당자B: 수정안 올렸어요.
09-08 16:00 담당자A: 오늘 회의에서는 표지 2안으로 결정했어요.
```

요약: 8일 오후 2시 회의를 잡았고, 사전에 수정안이 공유됐다. 회의 결과 표지 2안으로 결정됐다. 사용자에게 배정된 새 할 일을 임의로 만들지 않는다.

## 일반 채팅방: 내가 할 일

같은 가상 방에서 본인 닉네임이 ‘담당자B’라면 수정안 업로드는 이미 완료된 일이다. 미처리 목록에 다시 올리지 않는다. 직접 요청·약속한 미완료 업무가 없으면 확인한 범위에서 남은 할 일이 없다고 알린다.

## 오픈채팅방: 중요 이슈

입력: 오픈채팅방 ‘가상 행사 준비모임’, 2026-09-07, 중요 이슈.

가상 대화:

```text
10:00 운영A: 행사 장소 예약을 확인 중입니다. 확정되면 공지할게요.
10:05 참여B: 댓글에 적힌 장소와 지난 공지의 장소가 다른데 어디가 맞나요?
10:07 운영A: 아직 확정 전입니다. 이전 공지는 수정할게요.
```

이슈: 장소가 아직 확정되지 않았고 공지·댓글 간 안내가 달랐다. 운영자가 공지 수정 의사를 밝혔다. 참가자 전원에게 예약 업무를 배정하거나 장소가 확정됐다고 요약하지 않는다.

## 입력이 빠졌을 때

```text
사용자: 일반 채팅방 ‘새봄 프로젝트’, 어제 대화 읽어줘.
Codex: 조회 후 무엇을 정리할까요? 전체 요약 / 내가 할 일 / 중요 이슈 중
       여러 개를 선택하거나 원하는 작업을 직접 알려주세요.
```

원하는 결과를 묻고 답을 받기 전에는 대화 수집을 시작하지 않는다. 사용자가 처음부터 결과를 말했으면 다시 묻지 않는다.
